# MockSync API

- **Service:** `tools/mock-sync`, a local stand-in for the MOSIP server (Spring Boot 2.7, Java 11). Start:
  `cd tools/mock-sync && scripts/run-mock-sync.sh` (builds `target/mock-sync.jar` when missing).
- **Base URLs:** `https://localhost:8443` (desktop client; self-signed certificate `work/keys/tls-cert.pem`) and
  `http://127.0.0.1:8080` (Android debug build through `adb reverse tcp:8080 tcp:8080`; `--mocksync.http-port=0`
  turns it off). Both ports listen on 127.0.0.1 only (`server.address`, since 2026-10-10); `--server.address=0.0.0.0`
  opens them to the network.
- **Purpose:** answer, with MOSIP's message formats, the calls the unmodified Registration Clients make for login,
  initial sync, configuration sync, onboarding (IDA), packet sync and upload; plus admin calls for tests.
- **OpenAPI:** generated by springdoc at `/v3/api-docs`, browsable at `/swagger-ui.html`.

Complete reference (every endpoint, data sources, crypto details, settings, tests): `tools/mock-sync/README.md`.
Why it exists: [../adr/0004-mocksync.md](../adr/0004-mocksync.md).

## 1. Authentication

| Caller | Method |
|---|---|
| Registration client, login | `POST /v1/syncdata/authenticate/useridpwd` with a JWS signed by the machine's signing key (`kid` = key fingerprint); the response token is encrypted to the machine's public key. The machine must be registered first (`POST /admin/machines`), else `KER-SNC-155`. |
| Registration client, sync calls | The clients send the token from the login, but MockSync does not check it (a real MOSIP server does). The `keyindex` query parameter or path segment identifies the machine; an unknown machine gets `KER-SNC-155`. Responses are RS256-signed (`response-signature` header) and payloads encrypted to that machine's key, so only the registered machine can read them. |
| Admin calls (`/admin/**`) | No login. Loopback only (`LoopbackOnlyFilter`, which checks the decoded path, so `/%61dmin` is caught too); other hosts, and any request with an `Origin` header (a web page), get HTTP 403 |

Demo users are in `docs/test-data.md`; passwords are stored only as salted SHA-256 hashes (`data/users.json`).

## 2. Endpoints used by the liveness work

| Method and path | Use in PS04 |
|---|---|
| `GET /v1/syncdata/actuator/health`, `GET /v1/syncdata/actuator/info` | online check; Android version check |
| `POST /v1/syncdata/authenticate/useridpwd` | online operator login |
| `GET /v1/syncdata/configs/{keyIndex}` | delivers every `mosip.registration.liveness.*` key and the SFace SDK selection (signed, encrypted) |
| `GET /v1/syncdata/v2/clientsettings?keyindex=` | master data incl. `PermittedLocalConfig` rows (which liveness keys an operator may change locally) and FACE as an authentication method |
| `GET /v1/syncdata/v2/userdetails?keyindex=` | operators and supervisors |
| `GET /v1/syncdata/liveness/model-bundle` | online model update: streams the signed bundle `.zip` named by `mocksync.liveness-model-bundle` (`application/zip`); HTTP 404 when that setting is empty or the file is missing. No token and no machine check: the clients verify the bundle signature and hashes themselves. MockSync addition, not a MOSIP endpoint |
| `GET /v1/syncdata/getcacertificates` | device trust: MockMDS `rootca.cer` (DEVICE), renewed `rootcaftm.cer` (FTM and DEVICE), MockSync DEVICE CA for the Android built-in camera |
| `GET /registrationprocessor/v1/registrationstatus/getCertificate`, `POST .../registrationstatus/auth` | operator onboarding (IDA mock, `authStatus: true`) |
| `POST /registrationprocessor/v1/registrationstatus/sync`, `POST .../packetreceiver/registrationpackets` | packet sync and upload |
| `PUT /admin/config`, `GET /admin/config/{key}`, `DELETE /admin/config/{key}` | change liveness configuration during a demo |
| `GET /admin/packets`, `GET /admin/packets/{name}/liveness` | read back the `LIVENESS_*` evidence of uploaded packets |
| `POST /admin/machines`, `GET /admin/machines`, `DELETE /admin/machines/{name}` | machine registration |

All MOSIP-shaped responses use the envelope `{"id","version","responsetime","metadata","response","errors"}` with
HTTP 200, also for errors (`errors:[{"errorCode","message"}]`).

## 4. Use case: change the resident policy by sync (desktop run D8, Android run A12)

```bash
cd tools/mock-sync
scripts/set-config.sh mosip.registration.liveness.policy.registration=ALWAYS_ACTIVE   # PUT /admin/config
# Client: Synchronize Data (or an online login). It calls GET /v1/syncdata/configs/{keyIndex}, stores the key in
# GLOBAL_PARAM, and the next resident capture asks for challenges even for a high passive score; audit LV15
# {"changed":"mosip.registration.liveness.policy.registration"}.
scripts/set-config.sh --unset mosip.registration.liveness.policy.registration         # back to the shipped policy
```

## 5. Use case: online model update

The clients download a model bundle only from the URL in the synced key `mosip.registration.liveness.model.update_url`
(empty by default, so the feature is off). The download goes through the same checks as an offline import
([../design/online-offline.md](../design/online-offline.md) section 3).

```bash
cd tools/mock-sync
# Start MockSync with a signed bundle .zip, for example one built by scripts/make-sample-model-bundles.sh and zipped.
scripts/run-mock-sync.sh --mocksync.liveness-model-bundle=/path/to/bundle-1.3.1.zip
# Plain HTTP is accepted only to a loopback host: the desktop on the same laptop, Android through adb reverse.
scripts/set-config.sh mosip.registration.liveness.model.update_url=http://127.0.0.1:8080/v1/syncdata/liveness/model-bundle
# Client: Synchronize Data, then as a supervisor open the model import window (desktop header menu "Import liveness
# models"; Android Settings, Device Settings) and press "Check for model update". Audit LV15 on success, LV14 when
# the bundle is refused.
scripts/set-config.sh --unset mosip.registration.liveness.model.update_url                      # feature off again
```

## 6. Limits

Not a MOSIP server: no Keycloak, no biometric matching in IDA, no packet processing, no client-upgrade endpoint.
Keys and uploaded packets live in `tools/mock-sync/work/` (generated, never committed).
